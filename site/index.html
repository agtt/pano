The server panel that doesn't eat the server.

runs Next.js, Node and Bun apps, PHP sites and databases on your own Linux server. It is a single binary, it deploys from git, it gets HTTPS on its own and it keeps itself patched. The web UI idles around 7 MB.

ssh -L 7800:127.0.0.1:7800 root@server

Small on purpose.

A hosting panel is the one program on the server that every site depends on. It should be the easiest one to run and the hardest one to break.

One binary

Written in TypeScript on Bun and shipped as one self-contained file. No Docker, no Python, no license server.

The panel is two processes: a root agent and an unprivileged web UI.

Installed only when asked

PHP appears when the first PHP site needs it. MariaDB, PostgreSQL, Valkey, ClamAV, realtime and TURN are added on demand, so nothing unused sits on disk or in memory.

Sized to the machine

Database and cache memory is a share of the server's RAM. Builds, cron jobs and queue workers get a smaller CPU and disk share than your websites, so a deploy never slows a live site.

Everything a small fleet needs, nothing it doesn't.

One or a few Linux servers, modern apps next to classic PHP sites. Each block below replaces something you would otherwise assemble by hand.

Apps with git deploy

Next.js, Node.js and Bun, monorepos included. A push builds in a sandbox, starts a new release beside the old one, waits for the health check, then switches traffic. The previous release stays on disk, so rollback takes seconds and needs no rebuild. Push-to-deploy works with GitHub, GitLab, Gitea and Forgejo; any Node.js or Bun version can be pinned per app.

Instead of Vercel, Netlify, Coolify, or PM2 and nginx by hand.

PHP and WordPress

PHP 7.4 to 8.5, switchable per site with a revert. Every site runs as its own system user in its own PHP-FPM pool, inside an OS-level sandbox.

Instead of a shared PHP pool for every site.

Automatic HTTPS

Caddy at the edge: Let's Encrypt certificates, HTTP/3, compression and security headers. On-demand TLS covers customer domains. The config is validated before every reload.

Databases and services

MariaDB, PostgreSQL and Valkey on demand. "+ Database" creates the database and its user and writes DATABASE_URL into the app, so the password never reaches your browser.

Jobs and queues

Every cron job of every app and site on one page: last and next run, result, run now, logs. Jobs never overlap and failures alert. Optional monitor for BullMQ and Laravel queues.

Instead of Cronitor, Bull Board, Horizon.

Encrypted backups and disaster recovery

Full archives are encrypted with AES-256-GCM on the server; incremental backups use restic. Send them to one or two stores at once: Cloudflare R2, Backblaze B2, Hetzner, Wasabi, AWS S3 or MinIO. The store only ever sees ciphertext. Mark a store as protected and the panel never deletes from it, so a stolen server cannot wipe your backups.

The panel backs itself up too. Keep the one-line recovery kit in your password manager; on a fresh server, install && recover brings back admins, databases, sites and app data, then redeploys every app from git.

Instead of JetBackup, Acronis, or home-made backup scripts.

Move in from cPanel or CyberPanel

Import cPanel cpmove backups, or scan a live CyberPanel server and move sites one by one while the old panel keeps serving. Cutover has a one-click rollback.

Realtime and TURN

Pusher-compatible WebSockets (pusher-js, Laravel Echo and the Pusher SDKs work unchanged) and a coturn relay for WebRTC calls and peer-to-peer games. Both optional, nothing on disk until installed.

Private network

Built-in WireGuard with no account and no coordination server. Devices by key or QR code. Locks close SSH and the panel to everything but the VPN, and undo themselves if you lock yourself out.

Instead of Tailscale for admin access.

Alerts and self-update

Telegram alerts for failed deploys, crons and backups, services that go down, full disks and new serious vulnerabilities. update runs the new binary first and rolls back by itself if it does not come up within a minute.

A compromised web UI should not be a compromised server.

The panel is built around that one assumption. The part that faces your browser has no power of its own.

  1. You

    Browser over an SSH tunnel or the built-in VPN. Login is argon2id plus mandatory TOTP.

  2. localhost only

  3. Web UI

    Unprivileged user in a hardened systemd sandbox. It can ask whether a 2FA code is right, but it cannot make one.

  4. unix socket

  5. Root agent

    A fixed list of typed operations. Every argument is validated, no caller-supplied shell command runs as root, and the 2FA check happens here.

Sensitive actions need a fresh 2FA code checked by the agent: revealing secrets, changing environment variables or what an app runs, dropping or restoring data, adding a VPN device, cutover. Even a fully compromised web process cannot read your secrets or plant code into an app.

Sandboxed workloads
Each app and PHP site has its own system user, a read-only system, no new privileges, a syscall filter, a memory cap and no access to cloud metadata. Builds run in a sandbox too.
Vulnerability tracking
Nightly scan of OS advisories, app and site lockfiles (via OSV.dev), Node.js, PHP and WordPress core. OS security updates, PHP patch releases and the edge update themselves, never rebooting without you. Dependencies and plugins are reported, not changed.
Shield
Malware scanner with reversible quarantine, optional ClamAV deep scan, WordPress login brute-force bans and IP reputation lists. It is not a WAF, an EDR or DDoS protection, and says so.
Backups an attacker can't erase
Encrypted before upload, and protected stores refuse deletes from the server. The store test tells you whether a stolen key could still delete.
Audit page and log
A read-only audit of public ports, firewall, SSH, database bind and more, with the exact fix command for each finding. Every action lands in the audit log.
Network guard
nftables rules against SSH brute force and per-address HTTP floods, with no extra daemon. Secrets stay root-only and write-only from the UI.

What it doesn't do yet

Email hosting and a DNS server (meant to stay with Cloudflare or a mail provider), multiple servers from one panel, resellers and client roles, a file manager and per-site SFTP users, a WordPress toolkit, and preview environments for apps. It is a young project, tested end to end in VMs; the first real server migration is next.
